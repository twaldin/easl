# Changelog

Each version's section is its GitHub release's notes.

## Unreleased

- Notes render centred `mermaid` fences with the HTML kit's vendored Mermaid.js and container layout. An isolated WebKit renderer has a two-second render deadline and bounded bitmap output. Cold startup has a separate ten-second bound; preparation timeouts and renderer failures retry once before failure caching. Timed-out or invalid diagrams keep their source with a short explanation. Prose edits reuse cached bitmap layers instead of repainting diagrams through text layout. Resizing keeps the previous display until the new width is ready. Remote boards render on the viewing Mac. Board storage is unchanged, so 0.3.2 apps still show the fence as code.
- Plain wheel scrolling over oversized browser tiles reveals clipped edges before scrolling the page, including streamed browsers. Move-tool panning and Command-scroll zoom are unchanged.
- Restore afowic's `canvasKit.send` for agent-created local HTML tiles. One send per fresh native gesture can wake the creating agent with an ID-only notice. Page content is read only through an explicit labelled, escaped inbox tool result, never a custom message. Notice acknowledgement retains the payload; native retention, send rate, inbox batches and integration queues have explicit limits.
- The native app refuses ordinary `agent.prompt` messages that cannot fit its 256 KiB inbox-response budget. Easld and older apps may still accept larger messages; ordinary items over the omp extension's 1 MiB hold limit remain queued rather than bypassing that limit.
- Reject malformed native inbox negotiation and notice receipts before changing acknowledgements or holds. Oversized HTML singletons report their inbox-message budget rather than a full page queue.

## 0.3.2

easl 0.3.2 adds teaching features contributed by @afowic: math in notes and HTML, knowledge and reasoning graph diagrams, graded questions with confidence, and HTML tiles you can type into. It also adds remote-tab listing, fixes cancelled middle-click pans, and makes relayed browser streaming steadier.

### easld and the app

These changes need easld 0.3.2 for their full effect on remote boards:

- Grading answers and stamping `answer.correct` on the host, with confidence validation and grading in the answer mention.
- Creating, validating, and normalizing authored graphs, including reasoning levels and the 500-node and 2,000-edge limits.
- Normalizing stored question answers, discarding invalid confidence values and recomputing derived correctness.

A 0.3.2 app on easld 0.3.1 renders math, existing graph statuses and sources, and answered questions with grading and confidence. The older host preserves existing new props, but refuses new graph diagrams and graph prop updates with `invalid_params` (`diagram kind must be one of calls`). Frame-only graph moves still work. The older host does not gain the new grading or question normalization rules.

A 0.3.1 app on easld 0.3.2 can still view and edit boards, but shows math as literal TeX source and, in the RC fixture, a knowledge graph as a blank titled diagram. An answered question shows the selected option but omits confidence and the grading explanation. The release-candidate checks exercised both mixed-version directions through edits, saves, restarts, and reopening; all new-object props were kept byte for byte.

Math rendering, HTML keyboard ownership, remote-tab listing, and the middle-click pan fix are app-side changes. The browser-stream retirement fix runs on the Mac encoding the stream; it does not need a new easld.

### Board format

The board format is unchanged, still format 3. New graph data lives in `props.knowledge`, which older apps leave alone even when they refresh the legacy `props.graph` cache.

### Known limits

- Native Mermaid in notes is not in this release. A `mermaid` fence in a note shows as code; HTML tiles still draw Mermaid.
- `canvasKit.send` is not in this release.
- Math falls back to its source beyond its size and depth limits.
- Pan and zoom on boards of 500 or more objects are not smoother yet.

### Changes

- Rapid browser-stream churn drains old compression sessions before creating another encoder. Encoder destruction stays asynchronous; creating a new encoder can wait for retirement.
- Authored graph diagrams store their data in `props.knowledge`, separate from the legacy calls cache. Expanded details scroll within a capped panel while the graph remains visible.
- Diagram measurement respects the diagram kind and reports invalid authored graph input as `invalid_params`, consistent with easld.
- Display math in blockquotes excludes the quote markers from the formula.
- Question tiles can be graded and ask how sure the user is: `correct` marks the right option once answered (✓ or ✗, the right option's why on a wrong pick, and `answer.correct` stamped by easl, never the caller), `askConfidence` adds an optional confidence slider whose value the answer carries, both reach the asker's mention, and `easl ask` takes `--correct` and `--confidence`.
- HTML tiles take the keyboard for their text fields: Return on a selected tile, or a click in an input, textarea, select or contenteditable, gives the page the keyboard (typing, IME, copy/paste and Tab work), Esc or a click on the board hands it back, and a page that focuses a field on its own still cannot take it from the terminal.
- HTML field clicks use an isolated script world and expire after 300 ms. Moving focus, another native click, or a window activation change cancels pending keyboard permission.
- HTML keyboard clicks read the real DOM prototype getters and must land inside the active editable. Named forms and stale DOM focus cannot grant the keyboard for an outside click.
- HTML navigation commits, HTML or asset reloads, and web-content crashes revoke pending and granted keyboard permission. Rewriting a tile's page cannot carry its old keyboard grant into the replacement document.
- Consume the remaining middle-button events after a cancelled canvas pan instead of forwarding a stray release to the tile.
- Development: guard test-child cleanup after a failed spawn so it cannot signal the test runner's process group.
- Development: reconcile the design backlog with shipped remote-board features and restrict update proof to the remaining `agent-gui` guest.
- Host-file helpers require Bun 1.4.3 or later. Older Bun can discard successful subprocess output; CI pins the qualified runtime.
- Development: restore parallel Core CI with at most four active outer test cases per logical CPU. Cap synchronous codec work and isolate contention-sensitive fixtures. Keep linear large-line reads, the retained-runner zmx fixture, and unchanged assertions and deadlines.
- The Mac app's `board.list` includes open remote tabs with their host details, and board-scoped calls resolve their host board IDs while preserving private viewer trays and closed-local ownership, including tab-close requests.
- Notes typeset LaTeX: `$…$` inline and `$$…$$` on its own centered line with SwiftMath (currency, `\$`, code and unparsable formulas stay as written), and HTML tiles load KaTeX only when a page has math; note measurement, `size: "fit"` and `layout.check` account for it.
- Note math preprocessing bounds each entity search to 32 characters, so ampersand-heavy prose does not repeatedly scan the remaining note.
- Native note math separates nesting depth from formula size and typesetting work, so ordinary wide formulas such as matrices need not fall back. Over-limit and malformed formulas keep their monospace source in display and size-to-fit measurement. Native `\textcolor` uses SwiftMath's non-indexing color path.
- Diagram tiles draw caller-supplied knowledge and reasoning graphs (`kind: "graph"`): nodes with click-to-expand markdown detail, provenance that focuses the terminal it came from, and practice status (`taught`, `practiced`, `retained`, `weak`), up to 500 nodes laid out one column per reasoning depth. Nothing in them is computed from code. Authored input and storage use only `props.knowledge`; old apps can refresh `props.graph` without replacing authored data. Unsafe graph levels return `invalid_params` before integer conversion.

## 0.3.1

easl 0.3.1 adds keyboard shortcuts you can change and a Move tool for dragging tiles from their bodies. It also adds prompt delivery that reconciles lost replies without sending twice, safer board-file handling, and faster opening of big boards and remote content on slow links.

### easld and the app

These changes need easld 0.3.1 for their full effect on remote boards:

- Display-sized image reads through `image.preview` (#171).
- Idempotent prompt delivery and receipt-based reconciliation (#166).
- Excluding archived questions from host-side geometry (#169).

A 0.3.1 app on easld 0.3.0 falls back to original image bytes and legacy prompts (#177). Legacy prompts retain the old lost-reply risk: a draft can return after execution, and manually sending it again can duplicate it. The app does not resend automatically. Host-side archived-question geometry stays unchanged until easld updates.

A 0.3.0 app on easld 0.3.1 works, without gaining the new app features. The release-candidate mixed-version matrix exercised both app/host directions. The `release-compatibility` CI gate checks the current app's Core client against the previous easld and the previous Python SDK against the current easld. The coordinator deploys easld on deckbox right after the tag.

The remaining changes are app-side features and fixes, measurement tools, tests, or verification documentation. SSH compression and native terminal activity handling do not need a new easld. The new preview and prompt-receipt methods also exist on Mac hosts.

### Board format

The board format is unchanged since 0.3.0, still format 3. The Mac app now refuses unreadable or newer-format board files and leaves them untouched instead of opening empty replacements (#163).

### Remote performance

These studies measured individual changes, not a final 0.3.0-versus-0.3.1 comparison. They describe specific fixtures and links, not latency guarantees.

On a guest-loopback scratch easld, a 62-tile board was measured before and after distant-preview deferral (#167), image previews, and SSH compression (#171). This comparison does not isolate any one change. With 1 Mbit/s, 80 ms added RTT, and 1% loss in each direction, single observations were:

| Operation | Before | After |
|---|---:|---:|
| `seq 1 20000` | 11.64 s | 3.21 s |
| Code open | 4.16 s | 1.21 s |
| HTML first paint | 11.07 s | 4.12 s |

These are not population percentiles. The poor-link usable-open and browser latency gates were not qualified.

In a separate native-key study over guest-loopback SSH, echo measured 79 ms median / 97 ms p95 at 10 Mbit/s and 35 ms added RTT, with 500 spaced keys. On the 1 Mbit/s, 80 ms added-RTT link with 1% loss each way, the first matched 100-key pair measured 125 / 202 ms before the stale-HID fix and 133 / 216 ms after. The full 500-key poor-link cohorts measured 124 / 193 ms before and 128 / 200 ms after. These native-frame observations include tracing overhead and do not establish a native-key speedup.

For distant-preview deferral (#167), a six-core, 16 GiB macOS guest ran a 500-object fixture with eight terminals producing about 2 KiB/s each. Medians over five runs per variant and board kind were:

| Measurement | Local before / after | Guest-local scratch easld before / after |
|---|---:|---:|
| Open capture bound | 6.395 / 2.843 s | 6.101 / 2.972 s |
| Quiet post-open app RSS | 695.5 / 325.4 MiB | 714.1 / 335.3 MiB |

The open bound includes all eight terminal workers becoming ready and an accepted native viewport capture, not exact first presentation or completion of offscreen tiles. RSS is a main-app snapshot, not whole-system memory.

### Known limits

Pan and zoom on boards of 500 or more objects are not smoother yet. Opening a terminal still pauses the main thread for about 130 ms.

In that 500-object study, whole-board render medians rose from 3.732 to 3.881 s locally and from 7.052 to 7.480 s on guest-local easld. Remote zoom callback-gap p95 rose from 27.37 to 30.58 ms. Callback gaps are not GPU presentation times.

Deckbox-hosted boards on easld now work fully from a Mac. Browser relay, host-backed HTML and video, shared stacking, and whole-board rendering complete the remote-board work deferred from 0.2.8.

**easld and the app should match.** Update the Macs that view or draw boards and easld together. The coordinator deploys easld on deckbox right after the apps update. Running terminal sessions keep going.

The changes since 0.2.8 that need the new easld are:

- Browser relay, drawing-Mac switching, and streamed uploads (#143), plus the relay's adaptive video and refresh handling (#151).
- The `video` object type and exact video fitting (#141). HTML host assets, host-private HTTP, seekable byte reads, and GIF animation ship with the viewer.
- Late delegated diagram failures (#147).
- Browser-owner render routing (#157), including unseen-browser snapshots in whole-board renders (#160).
- Shared stacking and board format 3 (#158).
- Object expiry and `board.stale` (#159).

The other changes are Mac-side: terminal sharpness and scrolling (#99, #100), terminal HTML links (#101), the default board directory and New Folder picker (#150, #155), asynchronous board loading (#146), host-file transport and batching (#154 and the file-read part of #160), and automatic updates (#152, #156). Remote-use deferral needs updated drawing or hosting Macs and viewers; it does not update easld.

**Mixed versions.** Both releases use API schema version 2, so neither pairing is refused solely for its version. A 0.3.0 app can view and edit a board on 0.2.8 easld, but that host lacks browser relay and switching, video objects and fitting, expiry and stale listing, late diagram failures, and browser-owner render routing. New methods or parameters are refused rather than added by the app update. Viewer-side HTML assets, HTTP, GIFs, file-read improvements, and closed-board inspection still work. That host never converts older boards to shared stacking, and the new app draws its stored z values in one order. A shape or arrow drawn before a later tile can therefore appear beneath it until easld is updated. Mixed shape/tile restacking is not preserved when that old host saves and the board later migrates to format 3.

A 0.2.8 app can view and edit objects it knows on 0.3.0 easld, but it does not gain the new viewer features or serve relayed browser streams. A board containing the new `video` type cannot be decoded by that app. Update all viewers before adding video tiles.

**Board format 3.** Both new hosts migrate older boards once, preserving their previous visible stacking before allowing drawings and tiles to share one order. A 0.2.8 Mac app opens a format-3 board containing only types it knows, but draws shapes and arrows above tiles again. Saving with that app writes format 2 with the object's z values, not the format-3 stacking semantics, and drops object-expiry deadlines. On the next 0.3.0 load, migration restores the old tiers and renumbers z, losing any mixed drawing/tile order. If a saved board contains video tiles, the 0.2.8 Mac app cannot decode it and opens an empty board instead. Saving or closing that local board can overwrite its file and lose every object. A 0.2.8 easld instead refuses a format-3 file and leaves it unchanged. Do not open or save upgraded boards with older hosts.

**Auto-update.** easl › Install Updates Automatically is off by default. When on, it installs after 10 minutes with no local or remote use. Explicit installation still proceeds immediately and reports which remote sessions it interrupts.

**Updating from 0.2.4 or 0.2.6.** The update still runs the installed version's own install helper. If Update in 0.2.4 stops with nothing replaced, quit easl and install 0.3.0 from its zip on [GitHub Releases](https://github.com/twaldin/easl/releases), or run `brew upgrade --cask easl` for a Homebrew install. The install-helper fix shipped in 0.2.5, so 0.2.6 can use Check for Updates normally.

### Changes

- Mac boards read their files and check saved anchors off the main thread. Tiles appear before Git checks finish. Unverified anchor metadata stays out of API replies and events, then allowed anchors return without object revisions or undo steps. Undo and redo retain allowed anchors in local and remote viewers. Local and remote windows build their native shell and contents, then appear, on separate main-loop wakes, with shared preparation for concurrent opens. Client metadata loads off the main thread. Startup preserves saved tabs through interrupted restoration and registers background-only loads before API requests resume. Update tab restoration preserves separate groups, restores minimized groups without first showing them, and retains their native Window-menu entries. It does not hold the API behind remote connections and keeps the app running if a concurrent window closes. Closing during a pending open detaches terminal frontends before ending their sessions.
- Native board preparation decodes the app icon off main and preserves Retina representation sizes; a missing or damaged icon no longer prevents windows opening. Terminal command-path checks, shell probes and font-family discovery run off main, and delayed surfaces cannot attach to closed boards or closed remote hosts.
- Mac launch restoration disables background-attachment and Chrome text-size changes until saved settings are applied, so an early menu action cannot overwrite them with defaults.
- Development: performance probes now include late AppKit/Core Animation drawing and report individual long wakes with their matching CPU time. Earlier order-zero measurements are not full wall-budget passes; the board-load 100 ms target remains a separate qualification gate.
- Create a fresh board from File › Open Board… or the tab bar's + button using the picker's New Folder button while a local board is in front. Folder creation is unavailable on remote tabs. A fresh independent board requires a folder outside a Git repository; a folder inside one opens the repository's board. Existing folders still open normally.
- Remote renders use native viewer tiles and the browser's drawing Mac. Whole-board renders capture unseen browsers through the existing single-browser route without starting streams or accepting stale disconnected frames. HTML renders wait for initial loads and board-data fetches instead of capturing early blank pages.
- **HTML tiles load board data and scripts.** JSON, CSV, JavaScript, stylesheets, fonts, images and media use the board's host-file policy on local and remote boards. Loaded-file edits refresh the live page without reopening its tile; briefly parked pages resume without an unnecessary reload.
- **Video clips play on the board.** Create a `video` tile with a board path, optional poster and playback flags, or use `<video>` inside HTML. Both hosts serve seekable bytes in bounded reads, without a viewer-disk copy. MP4/MOV dimensions support exact fitting on easld as well as the Mac. Video file-URI references keep their original source across caller checkouts and repository-board adoption.
- **GIF image tiles animate** while live, locally and remotely, and stop their timers when parked.
- **Remote HTML can load a host-private HTTP page.** An allowlisted `http://localhost:5199` in an iframe or resource URL means the board host, not the viewing Mac. HTTP(S) uses memory-only origin grants and a dedicated SSH transport on that host's existing route and identity, separate from file reads. The host-independent viewer guard shares one canonical rule list across views and launches. This is a GET/HEAD resource proxy, not a cookie/session, POST or private WebSocket tunnel; unhandled requests fail closed.
- Streamed browser tiles select JPEG on fast measured links and bounded predicted H.264 on constrained links, including direct WAN Mac hosts. One settled high-quality H.264 refresh becomes the sharp prediction reference. Small changes retain that quality. Large input changes resume a warm motion encoder with an independent frame instead of encoding and discarding a sharp candidate. Periodic keyframe scheduling is disabled, and sharp IDRs never fall back to motion quality. Refresh uses one 16 KiB chunk per receipt. Input cancels queued refresh work at both source writers, and easld removes only superseded same-stream refresh chunks before the next motion frame. Already committed bytes finish intact. The quality target is maximum RGB error at most 8 and mean at most 1 through 200 documentation caret transitions and 30 transitions on a GitHub file view and dense table. VideoToolbox sessions drain and invalidate off the calling thread. Requires updated viewers, drawing Macs, and easld. Qualification results remain separate from this change description.
- **⌘-click an HTML report to see the page.** Local `.html` and `.htm` references without a line render in a browser tile from the resolved board root or a temp directory. Home-folder boards allow only temp pages. Dependency pages under `node_modules`, hosted and remote-terminal references, modified clicks and line references still open source. A second click goes to the same tile and refreshes changed HTML, including edits or clicks during loading. Adjacent assets are not checked. ⌘[ returns to the previous viewport. Ordinary local-file browser links keep their query and anchor when matching an existing tile.
- **Use the same live browser page from every easld viewer.** Easld relays private frames and input from the tile's drawing Mac, without storing page payloads or replaying input after reconnect. The title-bar selector moves drawing among attached Macs and explains the reload into that Mac's own profile. If the page's input relay cannot be prepared, its stream closes with a clear notice instead of silently losing queued input. Mac-hosted boards still draw only on their host.
- Streamed file inputs open the file picker on the driving viewer, including repeated clicks after choosing or cancelling a file and custom buttons that call `input.click()`. Passive page helpers preserve real user activation between a press and its release. Up to 32 files and 8 MiB total travel in memory, without staging files on easld or the drawing Mac. Folder and iframe uploads remain unavailable.
- Set `canvas.boardDirectory` in macOS user defaults to choose the default startup folder and the starting folder for Open Board… and the tab bar's + button on local boards or with no board open. Remote boards retain their existing picker behavior. Explicit launch roots still win; existing boards and their storage stay where they are.
- Remote host file reads batch small files and use four isolated SSH transports, separate from terminals and language servers. Video ranges and render inputs take the next slot before visible reads and background watches. Canceling a read preserves sibling transfers. Progressing transfers can exceed 20 seconds without failing as SSH status 255. Read-only transport failures get at most three attempts. Real file errors and Git mutations do not retry.
- Remote HTML tiles show the reason when a host image cannot load instead of silently returning not found. These are viewer-side fixes and do not require an easld update.
- **Install updates while your Mac is idle.** Enable easl › Install Updates Automatically, off by default, to download and verify newer releases and install after 10 minutes without input anywhere in your login session. Updates reopen your local and remote tabs without taking focus or changing Spaces. Agents can check with `easl app.update check` or install immediately with `easl app.update install`. Both paths keep the manual updater's signature, Team ID, and Gatekeeper checks. Atomic bundle replacement keeps a complete app at its installed path if interrupted. Failures report why when you next look at easl. Failed board recovery offers Retry or Discard without replacing your normal reopen list on later launches.
- Tiles can expire on both hosts with `expires` or `expiresIn`; `board.stale` lists cleanup candidates without changing the board, and the CLI accepts `--expires 2h` and `board.stale --older-than 7d`.

### Fixed

- Bring to Front and Send to Back order shapes, text, arrows, and ink together with tiles on local and remote boards. Saved boards retain their previous visible stacking until restacked. Update remote hosts and viewers together.
- Automatic updates wait for remote use too. Browser-stream input or changed frames, remote board input, and typing into attached terminals restart the ten-minute idle window. `easl app.update check` explains remote deferral. Explicit installation still proceeds immediately and warns which remote sessions it interrupts.
- Remote diagrams leave "Asking" and show late delegated failures after a zero-timeout reload returns. The last graph stays visible when its aim still matches. Requires the easld host update.
- **Scrolling up or down over a terminal no longer moves the board.** Over a terminal you hadn't clicked into, scrolling up or down panned the board unless the terminal had scrollback, so a full-screen program such as an agent's TUI, or a fresh shell, moved the board out from under the pointer. Vertical scrolling over a terminal now stays with it, focused or not: it scrolls the scrollback or reaches a program that reads the mouse, and over a full-screen program that doesn't it does nothing until you click in, so no stray ↑/↓ reaches a program you aren't typing in. Scrolling sideways still pans, ⇧-scroll with a mouse too, a trackpad gesture keeps whichever it started with, and scrolling over empty board pans as before.
- **Terminal text stays sharp on 1x displays.** On a non-Retina monitor, terminal text looked soft after a pan, a trackpad scroll or a ⌘0 jump, and sometimes from launch. Each live terminal now moves only its surface onto the nearest device pixel. Text is drawn 1:1 at 100% board zoom and content zoom 1 when the terminal's size is a whole number of device pixels. Fractional sizes, including proportional resizes and agent-written frames, can still look soft because Ghostty stretches its whole-pixel image to fit. Tile frames and the scroll origin stay exact, so arrows, `layout.check`, undo and the API keep their geometry. The surface moves by at most half a point on 1x screens and a quarter point on Retina.
- ⇧-wheel pans the board sideways over overflowing code and changes tiles too. Terminals and changes tiles keep a board pan when they missed both the previous gesture's end and the next gesture's start.
- Host language servers stop when their viewer's SSH link ends, including before the viewer receives the host PID. The viewer-supplied launcher owns cleanup on Linux and macOS.
- Host-closed boards allow panning, zooming, scrolling, and read-only text selection, including cached text panned back into view, without enabling edits or removing the closed banner. Cached Changes retain native drawing. Menus, shortcuts, accessibility close actions, code navigation, and links refuse changes while closed. Pending navigation, HTML queue handoffs, Changes applies and card reads cannot start stale work after closure or replace cached content across reopening. Inspection preserves focus, selection, attention markers, and the viewport, and ⌘J skips hidden closed tabs.

The extension now has omp put the session on disk before it reports it, as omp's own ACP clients do, so the path always resumes, on omp 18.6 and 18.8 alike.
- **A restarted tile keeps its session when the relaunch doesn't start.** `agent.restart --mode resume` records the relaunch on the tile (its session, model and thinking) once the old session is gone, but the killed omp could still be shutting down and its release, arriving after that, cleared the record. When the relaunch then failed to start (omp-update's restarts of three idle tiles hit a missing `omp` on the relaunch's PATH), two of the tiles were left with no session to resume. A release before the relaunched agent has reported is now taken as the killed agent's and ignored, so the tile keeps what it resumes and can be restarted again.
- **A terminal's command finds what its prompt finds, however easl was opened.** `easl agent spawn --command 'omp …'`, a resumed agent and `agent.restart`'s relaunch run the command in a login shell (`zsh -l -c`). That shell reads `.zprofile` but not `.zshrc` (bash: a `.bashrc` that returns when not interactive), and installers such as bun's and nvm's put their directory on PATH there. Opened from a terminal, easl passed on that terminal's PATH. Opened from Finder, the Dock, `open` or the updater's relaunch, it had launchd's `/usr/bin:/bin:/usr/sbin:/sbin`, and the command failed with `zsh:1: command not found: omp` while `omp` worked at the tile's prompt. The command now runs with the PATH an interactive login shell of yours sets up in the tile's directory, easl's `bin` still first. easl asks once per directory and asks again when a shell startup file changes. The shell after the command is unchanged. A startup file that hangs or fails holds a start up for at most 5 s, and the command then runs as before. easld's terminals (owned and hosted ones, their resumes after a reboot and their relaunches) ask the same of the host's shell at each start. On a deckbox, `node` had resolved to `/usr/bin/node` instead of nvm's.
- **Agents open another Mac's board.** `easl board.open_remote --host twaldin-work --board brd_…` opens that Mac's board in this easl as File › Open Remote… does: a tab of your board window, viewed live over ssh, with your current tab left in front unless `--select true`. The host is a name the picker shows (a tailnet Mac, a host opened before) or any ssh host; a board already open from that host is returned, never opened twice. Nothing about the board is written on this Mac; only the host joins the picker's recent hosts. An offline host fails `unavailable`, a board the host doesn't have open `not_found`.
- **`easl metrics` shows how long keys waited.** A `keys` line counts the keys typed into terminals and says how long they waited for the board's main thread before reaching the terminal (mean and max over the last minute, max since launch) and how long handing them to the terminal took. A main-thread stall holds every key typed during it and releases them together, late; when keys in a second waited 50 ms or more, one log line says how many and the longest wait. The hand-over ends where Ghostty queues the write for its IO thread; the write itself isn't timed yet.
- **A plain shell on a Linux host finds easld's socket.** The TS client, the `easl` CLI and the Python SDK defaulted to the Mac app's `~/Library/Application Support/Easl/easl.sock` everywhere, so on a host that runs easld (a deckbox) `easl` needed `EASL_SOCKET` set by hand outside a terminal tile. Off macOS the default is now easld's own socket: `$EASL_HOME/easl.sock`, else `$XDG_STATE_HOME/easl/easl.sock`, else `~/.local/state/easl/easl.sock`, still only when it exists and still after an explicit value and `EASL_SOCKET`. macOS is unchanged.
- **A remote board redraws its host-drawn tiles after a reconnect.** When the link to the host dropped and came back, the board was read again, but a code, changes, HTML, browser, image or diagram tile whose object hadn't changed kept the drawing it had: a "Not drawn" badge from a render that failed while the link was down, or an image from before the drop. Once both links to the host are back and the board has been read, each of those tiles now asks the host for a fresh drawing, once; ↻ on a tile still asks again.
- **easld runs the terminals of its own boards.** Started with `--own-terminals` (its Linux unit, `easld@.service`, now sets it), easld starts a terminal's session when it is created on one of its boards without `props.host`, and ends it, with zmx's log and the reports spooled for it, when the terminal is deleted. So `easl agent spawn` on a host that runs easld starts a real agent in easld's capped slice with no Mac attached, and `easl tell` reaches it. The session gets a hosted terminal's variables pointed at easld itself (`EASL_SOCKET` its socket, so the agent's reports, messages and spool go there; `EASL_BOARD_ROOT` the board's root there; no cmux variables, even ones easld inherited) and easld's home, the board and the tile as its owner: a session labelled with another home or board is neither taken over nor ended. A batch that fails starts nothing, and a session that can't start or end is logged in the board's history. Off by default, so an easld on a Mac leaves terminals to the app. To turn it on for a host, run `scripts/offload-setup.sh <host>`, then on the host `sudo install -m 0644 ~/.local/share/easl/easld@.service /etc/systemd/system/easld@.service`, `sudo systemctl daemon-reload` (without it the restart keeps the old command line) and `sudo systemctl restart easld@<user>.service`; the setup script prints these when the installed unit differs. Not yet: a Mac's tile attaching to them (attach by hand: docs/contracts.md "Owned terminals").
- **easld's agents come back after a reboot.** An easld that owns its terminals now remembers the boards it opens (`open-boards.json` in its home; a board already open when you update joins the next time it's opened) and reopens them when it starts. After a reboot each terminal there gets its session again: an agent that reported its session resumes it, with the options of the tile's own command (`omp --resume=<id>`, `claude --resume <id>`, `codex resume <id>`, `gemini --resume <id>`, `opencode --session <id>`, as the Mac's tiles resume), and one whose agent exited runs its command. Restarting easld itself starts nothing: sessions that still run are left as they are. A session easld started whose terminal is gone (deleted while easld was down, or one zmx wouldn't end) is ended a minute or so later, and the board's history says so; other homes' and boards' sessions are never touched. The resumed command is checked by easld's and the app's tests against one shared list of cases.
- **`easl agent.restart` works on easld's own agents.** On an easld that owns its terminals, `agent.restart` of one of them no longer needs a Mac: easld ends the session, waits until zmx no longer lists it, and starts the relaunch in a new one, resuming the agent's session (`--mode resume`) or starting it fresh (`--mode fresh`) with its model and thinking setting and your `--args`, as the Mac's tiles do. It refuses what a Mac's restart refuses (an agent working, a prompt or message it hasn't started, a draft, unless `--force`), messages queued for the killed agent come back to their senders, and the tile runs the relaunched command from then on, so a reboot resumes the new session; the killed agent's own exit report, arriving late, no longer wipes the session the relaunch resumes. If zmx stops answering, the restart gives up after 3 s instead of holding up every other terminal start and end. `agent.list` now says whether each of those terminals' sessions runs (`live`) and gives the agent's `pid`, or the session's foreground process when the agent reported none. The relaunched command is checked by easld's and the app's tests against one shared list of cases.

From this release on they carry over to updates.
- **Messages from other agents arrive in omp as IRC cards, not as your prompts.** A message from another terminal or a script (`easl tell`, `agent.prompt`, omp's `write agent://…` to an easl tile) is drawn as omp draws its own IRC messages (`💬 IRC ← reviewer@canvas` over the text), and omp's session history and retros print it as `[easl:message] …`, so they tell your prompts from agents' messages. Steering, waking an idle agent, the 20 wakes per sender an hour, Esc and acks work as before, and a turn a message starts gets the easl guidance and the board's standing orders as they are now.
- A board of working agents no longer stalls easl. omp changes a working tile's title every 80 ms (its spinner), and every change had easl walk the process table on the main thread to find what the terminal runs (two `KERN_PROCARGS2` reads parsed with their environments, a process-group listing); with 15 omp tiles that walk saturated the main thread, and the API stopped answering (`agent.prompt` timed out). A terminal now keeps the foreground job it found and, for up to a second, re-checks it with two or three `proc_pidinfo` calls; it walks again when the job has changed or the second is up.
- **Google Docs text is sharp in browser tiles.** A browser tile now tells its page the size and place of its "window" (`window.outerWidth`, `outerHeight`, `screenX`, `screenY`), as Safari does, at any zoom of the board or the tile. Before, outerWidth was 0, and Docs, taking outerWidth / innerWidth for the browser's zoom while the installed Safari is older than 26.4, drew its text at a quarter of the screen's resolution.
- A new browser tile you make without an address (New Browser Here, File › New Browser Tile… left empty) opens Google instead of a blank page. Agents' tiles still start blank.
- **Code tiles stop wrapping lines they have room for.** A new code tile (a ⌘-click on a `path:line`, Go to Definition, a link, an agent's tile without a frame) is as wide as its file's longest line needs, up to 200 columns, and `size: "fit"` widens to 200 columns (1546 pt) instead of about 120 before it wraps. Only longer lines, minified or generated, still wrap. Follow tiles keep their size.
- Bringing a board's tab forward (`board.open --select`, Go to Next Needs-You, Open Remote) while easl's window is on another Space no longer puts that tab on the Space you're working in: macOS switches to easl's Space and the tab comes forward there.
- The board's dots stay put under the tiles after a pinch past 100% (or under 10%). As the pinch bounced back, the dots kept a zoom a hair off the real one, and since they are laid out from a point far off the board, that left them up to 18 points out of place until the next pan.
- Browser tiles no longer depend on two private WebKit preferences being there: if a macOS release drops one, easl skips it instead of failing at every browser tile. docs/design.md lists each private WebKit interface easl uses, and what losing it would cost.
- `app.metrics` counts a request before its reply is sent, so a client that has the reply always finds the call there.
- Development: `scripts/dev.sh` launches through a command of your choice (`EASL_DEV_LAUNCHER`, e.g. a window guard on a shared Mac) instead of `open -g -n`.

## 0.1.0

easl is a native Mac app: one infinite board where your agents run in real terminals beside your code, a browser, html pages and diagrams.

- **real terminals.** Claude Code, Codex and any CLI agent run unmodified, rendered by libghostty with your Ghostty config.
- **your code, with your language server.** Hover, definitions, references, a git gutter against your branch, and live call graphs.
- **a browser your agents drive**, with the page's errors on the tile.
- **html pages and diagrams** your agents build beside their terminals.
- **reference anything in the next prompt.** Hyper-click a line of code, a DOM element, a note paragraph or a command's output.
- **agents keep running when you quit.** Terminals live in zmx sessions, so quitting or rebuilding easl leaves them working.
- **works with** Claude Code, Codex, opencode and Gemini CLI (before 0.60) with no setup, and omp with one symlink.

Requires macOS 14 or later on Apple silicon.
