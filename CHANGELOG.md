# Changelog

Each version's section is its GitHub release's notes.

## Unreleased

- **Remote boards say when their host closes them.** The viewer shows "<host> closed this board", keeps its last seen viewport (including scrolled terminal rows) read-only, and detaches terminals and browser streams. Reopening on either a Mac host or easld resumes the viewer automatically. Background viewers stop serving the closed board without forgetting its reopen address. Manually closed Mac tabs still accept their agents' reports and notifications. Requires updated hosts and viewers.
- Boards saved by older easld or Mac hosts drop outside-board anchor metadata when the host loads them, before any viewer receives it. The host removes refused note-fence `anchor=` attributes and code `props.anchor`, then saves only changed snapshots. Authored prose, fence bodies, captions, allowed anchors, revisions, and undo history stay unchanged. A second load performs no scrub save. Requires the host update.
- Host-generated code-tile anchors stay inside the board's file policy on easld and Mac hosts, including create, update, and background relocation. Outside paths and escaping symlinks add no source text to `props.anchor`. Inside-board files and permitted worktrees still anchor and relocate. Authored anchors and intentional local display access are unchanged. Code update events precede automatic anchor bookkeeping on both hosts. Requires the host update.
- **Navigate host code on remote boards.** Definitions, references, hover, Outline, and Go to use the host's checkout and language servers, never a local server against host paths. Missing-server messages name the command and host. Diagram tiles draw live call graphs and reload after host edits. easld persists computed graphs without changing the tile's revision or undo history. On easld, diagram `object.reload` requires an attached Mac viewer. Host text, locations, and graphs stay in the viewer's memory.
- Quitting while a language server is still being located no longer lets it start after shutdown.
- Host-generated note anchors stay inside the board's file policy on easld and Mac hosts. Outside paths and escaping symlinks add no source text to markdown and report `path refused`. Registered worktrees, pinned revisions, and permitted source-root overrides still work. Authored markdown and intentional local display access are unchanged. Requires the host update.
- CLI method help (`--help`, `-h`, and `easl help <method>`) stays local, includes parameters and results, and suggests close matches for unknown methods; browser help describes the cmux subset without connecting.
- **Open file references from remote terminals.** ⌘-click a path, a bare filename, or an absolute host path to open its host code tile at the line. One host call resolves the terminal's directory and file index, including wrapped references and pytest definitions. Repeated clicks re-aim the terminal's preview until the user keeps it. Missing files show a notice; outside paths and escaping symlinks are refused on the host. Option or Shift opens a separate tile. Both easld and Mac hosts work without a host upgrade.
- **Remote notes show live host excerpts and images.** Anchored fences, symbol-only fences, proposals, and pinned revisions use host file bytes with the local note renderer. A live note polls host metadata and follows edits, image replacements, and symbol moves. Host files stay in viewer memory, including cards and renders, and files over 4 MiB are refused. A transport failure keeps the last good display.
- **Agents can render an easld board through its Mac viewer.** `view.render` draws notes, HTML, images, code, changes, questions and attached terminals with the real tiles. Host-picture targets fail clearly instead of asking easld to draw them again. Images travel inline from the viewer; requested files are written only on easld's host. HTML `object.measure` and `size:"fit"` use exact WebKit layout with host-file reads while a capable Mac is attached, without `approximate`. With none attached, HTML remains unavailable.
- **Remote easld boards stay attached in the background.** Closing a sole-tab board window keeps its tiles and attachment alive while easl runs. A metadata-only reopen list restores attachments without showing windows. easl › Keep Remote Boards Attached is on by default; turning it off ends hidden attachments. Manually closing a tab beside others or using `board.close` detaches and removes its reopen entry. `client.list` shows each attached app and host. Reload remains unavailable for host-streamed browsers.
- HTML layout waits for images and for fonts first used by asynchronous excerpts. Initial page images load eagerly, including `loading="lazy"`, so exact offscreen sizes do not depend on scrolling.
- Failed HTML dimension reads return `unavailable` rather than an invented exact frame. A failed background-setting save leaves the current setting and attachments unchanged; unreadable reopen metadata prevents close instead of silently leaving an address to reopen later.
- Inline renders reject separately padded base64 fragments rather than returning image data a standard decoder cannot read.
- Large inline render replies no longer hold the viewer's main thread while checking the escaped JSON size against easld's 64 MiB limit.
- Login-shell probes no longer inherit unrelated sockets and pipes, so a shell cannot keep an exited SSH client's output open.
- Quitting tracks SSH process exit independently of output-draining callbacks, so a delayed reader cannot keep an already-reaped child registered.
- Remote metadata polling runs off the main thread; change notifications remain on it and are discarded if cancelled before delivery.
- Symbol-only note fences check the name before the declaration regex, avoiding expensive regex scans of long lines that cannot contain that symbol.
- Development: `browser-surfaces` adds Swift-host conformance for private stream ownership, acknowledgement credit, sequence deduplication, input validation, and dialogs without a listener.
- Development: Core CI keeps its two-job build cap and serial test mode while socket-handshake contention is investigated separately. Expensive routing checks run off the main actor; deadlines, polling and assertions are unchanged.
- **Remote image tiles draw on the viewing Mac.** Both easld and Mac-hosted boards use the real image tile, with host bytes held only in memory. A live tile polls host metadata every two seconds and reloads when the file changes. Paths outside the board root, escaping symlinks and files over 4 MiB show a refusal in the tile.
- **Board tabs stay on their Space.** Opening, closing or reopening a board no longer brings a replacement tab onto the Space you're using. Selecting a board on another Space, or in a minimized window, waits until you visit or restore its window instead of switching Spaces. Opening a folder through another easl launch follows the same rule. API close still discards the board's live surfaces immediately; an off-Space native tab finishes closing when its replacement can appear safely. ⌘J skips boards it cannot show and leaves their unseen attention markers untouched.

## 0.2.7

**Updating from 0.2.4.** The update still runs 0.2.4's own install helper. If Update in 0.2.4 stops with nothing replaced, quit easl and install 0.2.7 from its zip on [GitHub Releases](https://github.com/twaldin/easl/releases), or run `brew upgrade --cask easl` for a Homebrew install.

**Host updates.** Preserving input modes in newly created easld sessions, `board.close` on easld, merged-board ownership metadata for terminal attaches, unattended expiration of pasted images, and keeping failed-turn errors through agent restarts also need easld updated on the host. Re-run `scripts/offload-setup.sh <host>` on the Mac, then restart `easld@<user>` on the host (running sessions keep going). The corrected HTML-measurement error also needs the updated easld. The Linux restart-report fix needs refreshed host integrations, which the same setup command installs. The composer and delegated viewer calls, easld session-directory discovery and restart retries, direct attaches to a hosted terminal's own host, image staging itself, and live remote HTML work by updating the viewing Mac. Live HTML's host-file reads need Bun and Python 3 on the host, and git for refs. On a Mac app host, update that app for merged-board metadata, unattended image expiration, and failed-turn error retention.

- Development: the host-file cancellation regression waits for a complete client-ready PID before cancelling, including delayed process startup during the full native suite.
- Development: `dev.sh start` and `restart` launch unfocused on the current Space without yabai rules or window moves. Removed `dev.sh move` and the parking/testing Space controls.
- Development: `dev.sh shot` captures hidden windows in place without switching Spaces or taking focus. `EASL_DEV_FORBIDDEN_SPACES` can refuse captures on a forbidden showing Space.
- **Paste or drop images into remote terminals.** ⌘V, Edit › Paste, and image-file drops copy the image to the terminal's own machine before pasting its path. omp and Claude Code can attach that file instead of looking for it on the Mac. Ctrl+V also carries an image when the clipboard has no text, while text Ctrl+V still reaches the program unchanged. Local terminals stage under the GUI temporary directory. Ending sessions when closing a Mac board cancels pending input and removes their image copies. Copies are isolated by owning board in private directories and expire after seven days, checked at host startup and hourly while its owner runs. Remote and hosted terminals need the updated host app or easld for unattended expiration.
- **Scrolling text keeps its full width.** The raw note editor, easl Basics, code navigation popovers, and page error messages now keep overlay scroll bars even when macOS prefers legacy scroll bars. A scroll bar no longer narrows or rewraps their text. Fixed-row lists, tables, and the board canvas keep the system's scroll bars.
- **Close a board from an agent.** `easl board.close` and the Python and TypeScript SDKs close an open board on the Mac app or easld. Terminals keep running by default, and reopening the root brings them back. `endSessions:true` ends them instead. The Mac refuses its last open board rather than quitting. Closing a remote tab detaches the viewer without changing its host. Requests to a board while it closes answer `conflict`. Pending prompts cannot resume on a closed board. Closed boards stay in `board.list` with `open:false`, but leave the launch reopen list.
- **Hosted terminals attach when you view their board remotely.** The viewer connects directly to the terminal's `props.host` using its own SSH access instead of waiting for that session on the board host. It checks the board owner's home, tile and current or merged board labels before attaching. A copied tile still shows the owner's labels and refuses to attach. An unreachable terminal host shows ssh's reason and keeps retrying without attaching elsewhere.
- **The composer sends through attached terminals on easld boards.** The Mac viewer attaches as a client and serves prompts, terminal-screen reads, its window state, and exact AppKit text sizes for notes without host-file dependencies. Notes needing host fences or images still use easld's approximate fallback. Without a viewer, easld reports `unavailable` for those terminal and window calls and approximate text sizes. The viewer does not serve `view.render`, `view.snapshot` or `object.reload`, including for live HTML pages. HTML measurement on easld now reports `unavailable` rather than `invalid_params`.
- **Remote terminals find easld's sessions and survive an agent restart.** A Mac viewer now attaches through easld's own `<home>/zmx` directory instead of waiting in zmx's default directory. Mac app hosts keep using their GUI temporary directory. Remote and hosted attaches share one ownership check: the home and tile must match, and the board must be current or one it merged. A copied tile refuses another board's session and shows its owner. If `agent.restart` leaves a gap between sessions, the viewer waits until the new session appears. Deleting the terminal on the host still closes its viewer tile and attach loop. The API's `board.get` now reports optional merged board IDs so the viewer can check ownership.
- **Long-running agents report again after a fast Linux easld restart.** omp and opencode retain the observed socket inode between checks, preventing Linux from hiding a replacement by reusing its inode and timestamps. Previously, those agents could miss the restart and leave their tiles in the restored state.
- Development: lead rotation treats an already-exited CLI child as terminated when shutdown gets `ESRCH`, preserving its interrupted exit status and evidence.
- **Agents on deckbox keep paste and mouse working when first viewed.** A terminal easld started before any Mac attached could lose bracketed paste, mouse reporting, and keyboard modes on its first view. The creator now registers with zmx before it detaches, so the first viewer receives the screen and modes the program already set.
- **Long prompts and question notes show many rows.** The composer grows with its wrapped text to half the board window's height while it has the keyboard, then scrolls. A question's optional note wraps and grows to eight rows, with the page scrolling to keep its options and buttons reachable. Return answers, ⌥Return and ⇧Return add a newline, and Esc returns to the options. Both inputs keep overlay scroll bars, even with legacy scroll bars preferred, so scrolling never takes width from the text.
- **Swift 6.4 builds work with the Command Line Tools.** The test runner resolves swift-testing from the selected toolchain. For SwiftPM navigation, the empty-references hint now gives `swift build --build-system native --enable-index-store`, followed by an easl restart. Swift 6.4's SwiftBuild backend reports an index-store path different from the one it writes. Native builds avoid that upstream bug without symlinks or background builds.
- **Drag with the middle mouse button to pan.** Pressing the middle button and dragging moves the board with the pointer, from empty board or over any tile, as in Figma and Miro. A middle click that doesn't move still goes to what's under it, so a terminal's paste keeps working. Before, a mouse without a trackpad could only pan with the wheel, one notch at a time.
- **A Homebrew install opens without Gatekeeper's prompt.** After `brew install` or `brew upgrade`, the first launch waited on macOS's "downloaded from the Internet" confirmation. That prompt can open on a Space you aren't looking at, so a launch from an agent's shell (`open -g`) hung with nothing shown, and every `easl` command in your terminals waited behind it. The cask now clears the quarantine flag once easl is installed; the zip it installs is the notarized one the release published, pinned by its SHA-256. If clearing the flag fails, the install still succeeds and the first launch asks as before. This applies from the next `brew install` or `brew upgrade` on.
- **A restart keeps showing a turn that ended on an error.** When an agent's turn dies on an error (an API error, an abort), its tile goes `idle` with the error as its message. `agent.restart` (`--mode resume` or `fresh`) cleared that message, and the relaunched agent had no error of its own to report, so its first plain `idle` made the tile look like a healthy agent waiting for a prompt. A lead whose omp died on an API 400 right after compaction sat like that for three days after omp-update's hourly restart. The tile now keeps the error through the restart and through the relaunched agent's reports that start no turn, until the agent starts a turn, the same as without a restart. Looking at the tile doesn't clear it. `agent.list`, and every other result that describes an agent, reports it in the lifecycle's new `error` field, so a script can skip such a tile or tell someone without parsing the message.
- **HTML tiles on remote boards are live pages.** Pages draw on the Mac viewing the board, whether the host is easld or another Mac. They scroll, kit components work, and decisions persist on the host. Page images and code excerpts read the host's files with sandbox checks on that host, including descriptor-relative reads that refuse concurrent symlink swaps. The host needs Bun and Python 3. Clicked links create or reuse a browser tile on the host's board; that browser still shows as a picture. Remote page content stays in the viewer's memory, not its files or caches. Attached viewers do not accept `view.snapshot`, which would write remote content to a viewer-local scratch file. Public network requests use the viewer's network with an allowlist enforced on framed SVG documents too. DNS prefetch, explicit preconnect hints and anchor `ping` requests are disabled on remote HTML pages; the host's localhost and private names are not forwarded. Failed refreshes show the latest error and can be retried without dropping the connection.

## 0.2.6

**Updating from 0.2.4.** The update still runs 0.2.4's own install helper. If Update in 0.2.4 stops with nothing replaced, quit easl and install 0.2.6 from its zip on [GitHub Releases](https://github.com/twaldin/easl/releases), or run `brew upgrade --cask easl` for a Homebrew install.

**Hosted terminals.** The first two fixes below also need easld updated on the machine that hosts the terminals: re-run `scripts/offload-setup.sh <host>` on the Mac, then restart `easld@<user>` on the host (running sessions keep going).

- **Hosted terminals survive a board merge.** A terminal running on another machine was refused after its board merged into a repository board because its running session still named the old board. easl now recognises that merged board id when it attaches and rechecks the session, while sessions belonging to another board, home or tile remain protected. Until the host's easld is updated, new sessions and spawn rechecks on merged boards fail with unknown-parameter errors; those failures leave running sessions alone, but those tiles show an "unknown param merged" banner even while attached. Restarting a terminal still relaunches its session.
- **Hosted agents can report as soon as easld restarts.** Restarting easld removed their relayed sockets until the Mac's next 30 s keepalive, leaving hosted agents unable to report or message. easld now restores those sockets before its own API starts when the Mac's ssh connection survives.
- **A remote board draws the tiles you're looking at, and none of them time out.** Opening another Mac's board with many HTML, code or browser tiles asked the host for every tile's drawing at once. The host draws one request at a time, so on a board of 264 HTML cards 12 of the 20 cards in view said "Not drawn: view.render timed out after 30.0s" for good, and the host spent 80 s drawing cards nobody was looking at. The viewer now asks only for tiles in or near its view, the ones in view first and together in as few requests as the host can send back, with one request out at a time, and a tile asks when you scroll it into view. On a board like that one the cards in view are drawn about 3.5 s after opening (2 s after the board appears), none time out, and the host draws 42 cards instead of 264. It works with hosts on any easl that opens remote boards.

## 0.2.5

**Updating from 0.2.4.** The update that installs 0.2.5 still runs 0.2.4's own install helper, so the updater fix below applies from the next update on. If Update in 0.2.4 stops with nothing replaced, quit easl and install 0.2.5 from its zip on [GitHub Releases](https://github.com/twaldin/easl/releases), or run `brew upgrade --cask easl` for a Homebrew install.

- **easl samples itself when its main thread stalls.** When the board's main thread has been stuck in one piece of work for a second (keys held, nothing redrawing), easl runs the system's `sample` on itself for that second, while the stall is still going, into `~/Library/Application Support/Easl/stalls/<time>.txt` (the development instance's own home under `EASL_HOME`), and the log line naming the stall's cause starts with that file, so a stall nobody caught in the act leaves its backtraces behind. At most one sample every five minutes, the newest twenty kept; `easl metrics` says how many were taken and the newest. Measured runs (`EASL_DEV_PERF=1`) don't sample.
- **Updates install where easl can't change its own app's dates.** Where macOS refuses to change the installed app's dates, Update stopped with nothing replaced. easl now protects the old app for rollback without changing its dates.
- Development: `scripts/rotate-lead.ts` performs a guarded fresh lead restart and an acknowledged out-of-band handoff with reserved delivery time and recorded evidence.

## 0.2.4

- **A folder's board survives `git init`.** A board made for a folder before it was a git repository (`~/dev/tiktok`, then `git init` and a commit) was replaced by a new, empty board when easl reopened the folder: the folder now opens its repository's board, and the step that folds older boards into repository boards ran once per Mac and never looked again. When a repository's board loads, easl now takes in the boards of folders inside that repository that were made before they were in git. On an empty repository board (including the empty one easl 0.2.3 saved in its place) the objects stay where they were, with the same ids and frames; on one you have added to since, they arrive as a region beside your work. Messages queued for its terminals and their old names come along, and a subfolder's notes, HTML pages and diagrams keep reading that subfolder (this also holds for per-branch boards merged at launch, which lost those before). The old file moves to `boards/pre-repo-migration/`, and the repository board lists it in `repo.merged`, so agents still using the old board id reach the repository board. A folder board already loaded in the current session waits for the next launch, even after it is closed. easld does the same, and an easld that reopens its boards at start reopens such a folder's board as its repository's board, its owned terminals' running sessions included, instead of dropping it.
- **A message to an agent on another machine arrives once.** omp's `write agent://name` to an easl tile whose terminal runs on another host (a deckbox) sometimes arrived twice, seconds apart, with two message ids. easl reads such a terminal's text over ssh before it queues the message, which took 2.6 to 10 s. easl's omp extension gave up after 1.5 s and reported the write as failed, though easl still queued the message. The dotfiles' omp-inbox extension then sent the text again with `easl tell`. `agent.prompt` now takes the sender's own message id (`message`, `easl tell --message`): an id already queued for the terminal answers with that message (`duplicate: true`) and queues nothing, even when the first attempt is still reading the terminal. The same id sent to several terminals is a message to each. The extension sends one id for every attempt at a write, waits up to 20 s for easl, and when it still fails it leaves the id in the tool result (`details.easl.message`) for the next handler to send again with. A server on an older release refuses the id before it queues anything, and then gets the write without one. omp-inbox needs its own update to pass that id on.
- **omp tiles resume their session after a reboot.** Killing a terminal's session (a reboot, or zmx stopped and easld restarted) hangs up its omp, and omp ends its session then just as on `/exit`. easl's omp extension took that as the user leaving and released the tile, which erased the session easl had recorded, so the tile came back running its command: a fresh omp with none of the conversation. The extension now releases only when no hangup or SIGTERM came first, so the tile comes back as `omp --resume=<its session file>`; `/exit` still releases, and a tile you ended stays ended. Claude Code tiles keep their session the same way when Claude says it ended for `other` reasons: a hangup or SIGTERM, and any other end Claude files under `other` (its `/exit` says `prompt_input_exit` and still releases). Codex and Gemini CLI give one reason for every end, so easl can't tell and releases their tiles whenever they end, as before. easld and the Mac's tiles now both resume omp by its session file, as `agent.restart` does, or by its id when that file is gone (omp's `/move` renames it; a hosted tile's file is on its host, where the Mac can't check, so it keeps the path), and easld's log says, for each session it starts, whether it resumes the tile's agent or runs its command, and why.
- **Terminals redraw slowly while you're away.** After a minute without input anywhere on the Mac, every terminal redraws at most twice a second (a working agent's spinner still moves); the first key, click or scroll, in easl or any other app, brings back full rate within a second. Only drawing slows: the terminal reads its program's output, titles change, agent reports and `agent.read` answer at full speed, so nothing is missed. Fifteen agent terminals on a visible board kept the GPU and WindowServer busy all night for an empty chair; now they don't. `easl metrics` counts redraws (`terminal.draw`). Programs that ask the terminal to report its visibility (DEC mode 2033; none easl ships does) are told hidden and visible at that rate.
- **A restart keeps the answer you haven't read.** `agent.restart` (`--mode resume` or `fresh`) cleared the tile's lifecycle, its needs-you badge with it: a tile `done` with an answer you hadn't looked at came back unbadged, gone from ⌘J and showing no `done` in `agent.list`, so omp-update, which leaves such tiles alone, skipped them. The tile now stays `done` and unseen throughout the restart, including an early release from the killed agent without withdrawing or posting its notification again, and through the relaunched agent's reports that start no turn (`idle`, or aider's startup `unknown`; its message stays too). Looking at the tile clears it, and so does the relaunched agent starting a turn, as without a restart; a tile you had already seen restarts unbadged as before. `agent.wait` waits for the relaunched agent's first report even after you see the answer or close and reopen the board, and fails within its first-report grace if none arrives; a session report wakes waits already pending.

## 0.2.3

- **easl updates itself.** A minute after launch and then daily, easl reads easl.sh/latest.json; when a newer version is out, an **Update** button appears at the top right of every board window, and easl › Check for Updates… checks now (and says when easl is up to date). Update shows "Update to X? easl quits and reopens; your terminals keep running." with Release Notes beside it, then downloads the release into easl's support folder, checks its size and SHA-256 against latest.json, its signature, Team ID and notarization, and its version, quits easl like ⌘Q, swaps the app where it is and reopens it. Any failure leaves the running easl as it was and says why; if the swap itself fails, the old version is put back and the next launch says why. A Homebrew install updates the same way (`brew outdated` lists easl until `brew upgrade --cask easl`). Testing: `EASL_UPDATE_URL` reads another latest.json, and `scripts/dev.sh` passes it through; development instances never check by themselves.
- **Links in a question open with a click, and its text copies.** A web address an agent writes in a question (`http://twaldin-home:5199/home?studio`, `https://…`) shows in link color, and a click opens it in a browser tile beside the question, as its context links do; the pointer turns to a hand over it, and VoiceOver lists it as a link. Drag over the question's text to select any part of it, from a link too, and copy it with ⌘C or the context menu's Copy. Number keys, Return, the note field and Esc work as before, with text selected and after. This holds for an answered or closed question's text as well, and at any board or content zoom.
- **Restarting an omp tile that hasn't replied yet works on omp 18.8.** omp writes a session's file only once it has a reply, but easl's omp extension reported the session's path from the start, and `agent.restart --mode resume` (and a reboot's resume) relaunched with `omp --resume=<that path>`. omp 18.6 opened a fresh session there; omp 18.8 refuses a path with no file (`Session "…" not found.`) and exits, so a just-started tile, or one after `/new`, came back as a shell with no agent. The extension now has omp put the session on disk before it reports it, as omp's own ACP clients do, so the path always resumes, on omp 18.6 and 18.8 alike.
- **A restarted tile keeps its session when the relaunch doesn't start.** `agent.restart --mode resume` records the relaunch on the tile (its session, model and thinking) once the old session is gone, but the killed omp could still be shutting down and its release, arriving after that, cleared the record. When the relaunch then failed to start (omp-update's restarts of three idle tiles hit a missing `omp` on the relaunch's PATH), two of the tiles were left with no session to resume. A release before the relaunched agent has reported is now taken as the killed agent's and ignored, so the tile keeps what it resumes and can be restarted again.
- **A terminal's command finds what its prompt finds, however easl was opened.** `easl agent spawn --command 'omp …'`, a resumed agent and `agent.restart`'s relaunch run the command in a login shell (`zsh -l -c`). That shell reads `.zprofile` but not `.zshrc` (bash: a `.bashrc` that returns when not interactive), and installers such as bun's and nvm's put their directory on PATH there. Opened from a terminal, easl passed on that terminal's PATH. Opened from Finder, the Dock, `open` or the updater's relaunch, it had launchd's `/usr/bin:/bin:/usr/sbin:/sbin`, and the command failed with `zsh:1: command not found: omp` while `omp` worked at the tile's prompt. The command now runs with the PATH an interactive login shell of yours sets up in the tile's directory, easl's `bin` still first. easl asks once per directory and asks again when a shell startup file changes. The shell after the command is unchanged. A startup file that hangs or fails holds a start up for at most 5 s, and the command then runs as before. easld's terminals (owned and hosted ones, their resumes after a reboot and their relaunches) ask the same of the host's shell at each start. On a deckbox, `node` had resolved to `/usr/bin/node` instead of nvm's.
- **Agents open another Mac's board.** `easl board.open_remote --host twaldin-work --board brd_…` opens that Mac's board in this easl as File › Open Remote… does: a tab of your board window, viewed live over ssh, with your current tab left in front unless `--select true`. The host is a name the picker shows (a tailnet Mac, a host opened before) or any ssh host; a board already open from that host is returned, never opened twice. Nothing about the board is written on this Mac; only the host joins the picker's recent hosts. An offline host fails `unavailable`, a board the host doesn't have open `not_found`.
- **`easl metrics` shows how long keys waited.** A `keys` line counts the keys typed into terminals and says how long they waited for the board's main thread before reaching the terminal (mean and max over the last minute, max since launch) and how long handing them to the terminal took. A main-thread stall holds every key typed during it and releases them together, late; when keys in a second waited 50 ms or more, one log line says how many and the longest wait. The hand-over ends where Ghostty queues the write for its IO thread; the write itself isn't timed yet.
- **A plain shell on a Linux host finds easld's socket.** The TS client, the `easl` CLI and the Python SDK defaulted to the Mac app's `~/Library/Application Support/Easl/easl.sock` everywhere, so on a host that runs easld (a deckbox) `easl` needed `EASL_SOCKET` set by hand outside a terminal tile. Off macOS the default is now easld's own socket: `$EASL_HOME/easl.sock`, else `$XDG_STATE_HOME/easl/easl.sock`, else `~/.local/state/easl/easl.sock`, still only when it exists and still after an explicit value and `EASL_SOCKET`. macOS is unchanged.
- **A remote board redraws its host-drawn tiles after a reconnect.** When the link to the host dropped and came back, the board was read again, but a code, changes, HTML, browser, image or diagram tile whose object hadn't changed kept the drawing it had: a "Not drawn" badge from a render that failed while the link was down, or an image from before the drop. Once both links to the host are back and the board has been read, each of those tiles now asks the host for a fresh drawing, once; ↻ on a tile still asks again.
- **easld runs the terminals of its own boards.** Started with `--own-terminals` (its Linux unit, `easld@.service`, now sets it), easld starts a terminal's session when it is created on one of its boards without `props.host`, and ends it, with zmx's log and the reports spooled for it, when the terminal is deleted. So `easl agent spawn` on a host that runs easld starts a real agent in easld's capped slice with no Mac attached, and `easl tell` reaches it. The session gets a hosted terminal's variables pointed at easld itself (`EASL_SOCKET` its socket, so the agent's reports, messages and spool go there; `EASL_BOARD_ROOT` the board's root there; no cmux variables, even ones easld inherited) and easld's home, the board and the tile as its owner: a session labelled with another home or board is neither taken over nor ended. A batch that fails starts nothing, and a session that can't start or end is logged in the board's history. Off by default, so an easld on a Mac leaves terminals to the app. To turn it on for a host, run `scripts/offload-setup.sh <host>`, then on the host `sudo install -m 0644 ~/.local/share/easl/easld@.service /etc/systemd/system/easld@.service`, `sudo systemctl daemon-reload` (without it the restart keeps the old command line) and `sudo systemctl restart easld@<user>.service`; the setup script prints these when the installed unit differs. Not yet: a Mac's tile attaching to them (attach by hand: docs/contracts.md "Owned terminals").
- **easld's agents come back after a reboot.** An easld that owns its terminals now remembers the boards it opens (`open-boards.json` in its home; a board already open when you update joins the next time it's opened) and reopens them when it starts. After a reboot each terminal there gets its session again: an agent that reported its session resumes it, with the options of the tile's own command (`omp --resume=<id>`, `claude --resume <id>`, `codex resume <id>`, `gemini --resume <id>`, `opencode --session <id>`, as the Mac's tiles resume), and one whose agent exited runs its command. Restarting easld itself starts nothing: sessions that still run are left as they are. A session easld started whose terminal is gone (deleted while easld was down, or one zmx wouldn't end) is ended a minute or so later, and the board's history says so; other homes' and boards' sessions are never touched. The resumed command is checked by easld's and the app's tests against one shared list of cases.
- **`easl agent.restart` works on easld's own agents.** On an easld that owns its terminals, `agent.restart` of one of them no longer needs a Mac: easld ends the session, waits until zmx no longer lists it, and starts the relaunch in a new one, resuming the agent's session (`--mode resume`) or starting it fresh (`--mode fresh`) with its model and thinking setting and your `--args`, as the Mac's tiles do. It refuses what a Mac's restart refuses (an agent working, a prompt or message it hasn't started, a draft, unless `--force`), messages queued for the killed agent come back to their senders, and the tile runs the relaunched command from then on, so a reboot resumes the new session; the killed agent's own exit report, arriving late, no longer wipes the session the relaunch resumes. If zmx stops answering, the restart gives up after 3 s instead of holding up every other terminal start and end. `agent.list` now says whether each of those terminals' sessions runs (`live`) and gives the agent's `pid`, or the session's foreground process when the agent reported none. The relaunched command is checked by easld's and the app's tests against one shared list of cases.

## 0.2.2

- **Signed, notarized, and on Homebrew.** easl is signed with a Developer ID and notarized by Apple, so a downloaded zip opens like any app, with no `xattr` step. `brew install --cask twaldin/tap/easl` installs it, and `brew upgrade --cask easl` updates it (it quits easl first; terminal tiles keep running). Because easl's signature changed, permissions you granted it before (Accessibility, Screen Recording, Full Disk Access) need granting once more: in System Settings › Privacy & Security, remove easl from each of those lists and add it back. From this release on they carry over to updates.
- **Messages from other agents arrive in omp as IRC cards, not as your prompts.** A message from another terminal or a script (`easl tell`, `agent.prompt`, omp's `write agent://…` to an easl tile) is drawn as omp draws its own IRC messages (`💬 IRC ← reviewer@canvas` over the text), and omp's session history and retros print it as `[easl:message] …`, so they tell your prompts from agents' messages. Steering, waking an idle agent, the 20 wakes per sender an hour, Esc and acks work as before, and a turn a message starts gets the easl guidance and the board's standing orders as they are now.
- A board of working agents no longer stalls easl. omp changes a working tile's title every 80 ms (its spinner), and every change had easl walk the process table on the main thread to find what the terminal runs (two `KERN_PROCARGS2` reads parsed with their environments, a process-group listing); with 15 omp tiles that walk saturated the main thread, and the API stopped answering (`agent.prompt` timed out). A terminal now keeps the foreground job it found and, for up to a second, re-checks it with two or three `proc_pidinfo` calls; it walks again when the job has changed or the second is up.
- **Google Docs text is sharp in browser tiles.** A browser tile now tells its page the size and place of its "window" (`window.outerWidth`, `outerHeight`, `screenX`, `screenY`), as Safari does, at any zoom of the board or the tile. Before, outerWidth was 0, and Docs, taking outerWidth / innerWidth for the browser's zoom while the installed Safari is older than 26.4, drew its text at a quarter of the screen's resolution.
- A new browser tile you make without an address (New Browser Here, File › New Browser Tile… left empty) opens Google instead of a blank page. Agents' tiles still start blank.
- **Code tiles stop wrapping lines they have room for.** A new code tile (a ⌘-click on a `path:line`, Go to Definition, a link, an agent's tile without a frame) is as wide as its file's longest line needs, up to 200 columns, and `size: "fit"` widens to 200 columns (1546 pt) instead of about 120 before it wraps. Only longer lines, minified or generated, still wrap. Follow tiles keep their size.
- Bringing a board's tab forward (`board.open --select`, Go to Next Needs-You, Open Remote) while easl's window is on another Space no longer puts that tab on the Space you're working in: macOS switches to easl's Space and the tab comes forward there.
- The board's dots stay put under the tiles after a pinch past 100% (or under 10%). As the pinch bounced back, the dots kept a zoom a hair off the real one, and since they are laid out from a point far off the board, that left them up to 18 points out of place until the next pan.
- Browser tiles no longer depend on two private WebKit preferences being there: if a macOS release drops one, easl skips it instead of failing at every browser tile. docs/design.md lists each private WebKit interface easl uses, and what losing it would cost.
- `app.metrics` counts a request before its reply is sent, so a client that has the reply always finds the call there.
- Development: `scripts/dev.sh` launches through a command of your choice (`EASL_DEV_LAUNCHER`, e.g. a window guard on a shared Mac) instead of `open -g -n`.

Nothing else reaches the agent while it restarts, nothing is relaunched until the old session is confirmed gone, and messages still queued for the killed agent (only a forced restart has any) bounce back to their senders rather than reach the relaunched one. `easl agent spawn` makes a named agent terminal and prompts it once it's ready. - A visible terminal printing now and then no longer starts a new display-link thread for every line: each terminal view keeps its own display link, paused while idle.
- An agent's big `object.batch` no longer holds the main thread for its arrows out of view or the cards of its new tiles: those run after the batch's own stretch, each on its own, so the board keeps drawing between them (the longest stretch of a 101-write batch on a 339-object board went from about 95 to 55 ms).

## 0.2.0

- **remote boards (client mode).** A board another Mac's easl hosts opens in a window of its own, `<board> @ <host>`, over ssh: notes, questions and drawings are native and editable, terminals are the host's live sessions, code, changes, HTML, browser, image and diagram tiles are the host's rendering under a read-only badge (↻ redraws), and the composer prompts the host's agents. Your moves, edits, answers and deletes show at once and go to the host, whose version wins; a lost link shows a banner and keeps the board as last seen. Nothing about a remote board is saved on your Mac, and it has no undo yet. API: `view.render` `inline: true` returns the PNG in the reply (`data`, base64); `agent.prompt` `composer: true` (with `answer`) sends as the user's composer does.
- **agents message each other without typing.** `easl tell bob "…"` (or `agent.prompt`) reaches an omp tile running easl's extension out of band: it arrives as a message naming the sender, a half-typed draft and an open question stay put, a working agent is steered (`--when next-turn` waits for the turn to end), and at most 20 wakes per sender per hour. omp's `write agent://bob` reaches easl tiles too. Addresses are `name@board`; a renamed tile keeps its old name. Scripts send with `--from <label>`. Queued messages survive an app restart and are acked only once omp has recorded them. A message whose agent exits, is killed or starts another session before taking it is never lost: it comes back to the sender as "undelivered to bob@…", or lands in the board's history; a killed agent's tile answers `unavailable` until an agent starts there again. Agents without an integration, and the composer, still type. (Schema: `agent.inbox`, `agent.prompt` `when`/`from`/`delivery`, the `ambiguous` error, history kind `message`.)
- **boards reopen where you left them.** Each board comes back at its zoom and spot on relaunch, kept on your Mac (not in the board file, so shared boards stay yours to look at your way).
- **chrome text size.** View ▸ Increase / Decrease / Reset Chrome Text Size (⌥⌘= / ⌥⌘- / ⌥⌘0) scales the tray and tile title bars to 150%, separate from board zoom and a tile's content zoom.
- **web links open in a browser tile beside where you clicked.** A ⌘-click on a URL in a terminal, a link in an HTML page or a note, a ⌘-click on a URL in code, and `open <url>` or `$BROWSER` run in a terminal tile (the new `view.open_url` call) show the page in a tile beside the source; a tile already showing that address is shown instead of a duplicate. ⌥-click (⌥⌘ in a terminal or code) sends the URL to your default browser; `/usr/bin/open` stays the system's.
- **browser tiles behave like a browser.** Sign-in popups keep `window.opener` (a popup opens in a tile beside its page and closes with it), downloads land in ~/Downloads with a progress pill in the address bar, file uploads, `alert`/`confirm`/`prompt`, HTTP logins and client certificates, per-site camera and microphone prompts, location, Find in Page (⌘F), File › Print Page…, fullscreen video, other apps' links (`mailto:`, `zoommtg:`) after asking, named browser profiles (the tile's Profile menu, `props.profile`), Reload When Files Change for local pages (`props.reloadOnChange`), and a user agent that follows your installed Safari.
- **Password managers and other Safari extensions in browser tiles** (macOS 15.4 or later). Add one from easl › Browser Extensions › Add Extension… (an app such as Bitwarden that includes a Safari extension, an `.appex`, or an unpacked folder), see what it asks for, and click its icon in the address bar to unlock and fill. Passkeys aren't supported.
- **an API conformance suite** (`conformance/`): scripted conversations with the socket API, recorded from the app, that replay against any server and print what differs (docs/testing.md).
- **easld** (`easld/`): the Go server that will own boards and the API. It serves the socket API from the same board files and passes 17 of the 19 conformance scenarios, `view.open_url` and `app.metrics` (its own request, event, write and save counters) included; the app doesn't use it yet. It won't start on a home the app or another easld is using, or take over a socket another server answers on, and it leaves alone a board file it can't fully read (one from a newer app) instead of overwriting it.
- **the composer.** The tray is a prompt box: ⌘I from anywhere, ⌘↩ sends. Hyper-clicks drop inline `[n]` tokens where you type, the words after a token are its note, and deleting a token unstages it. Send one prompt to several terminals at once; a blocked agent's question shows in the composer and your text answers it; ↑ recalls what you sent, and drafts survive board switches and restarts. API: `tray.drain` takes the `prompt` an integration is about to submit, so the drain of a prompt sent from the composer takes exactly its own mentions, however the agent rewrote the text (the bundled hooks and extensions pass it).
- **agent write bursts no longer freeze the board.** An agent writing tile after tile used to re-route every arrow on the main thread once per write (a 139-write burst on a 339-object board: 34 s of CPU, the UI frozen for 45 s). The board now routes once the burst ends, off the main thread, while arrows bound to a written tile follow it as it changes.
- **`easl metrics`** (`app.metrics`, View › Performance HUD): what easl's work costs (main-thread busy time and stretches, per-method API cost, events, writes per agent, routings, saves, live tiles, CPU, memory and wakeups), and an `app.log` line naming the cause of any main-thread stretch over 250 ms.
- **⌘J works across boards.** When the board you're on has nothing more that needs you, ⌘J goes on to the next open board that does, brings its tab (or window) forward and lands on the item; after the last board it starts over. Each board's tab title (and its entry in the Window menu) shows how many things need you there, "easl (2)".
- HTML tiles panned or zoomed out of view and back within 30 s no longer reload their page.
- **agents ask you on the board.** `easl ask "…" --option id=label[:why] … --recommend id` posts a question tile: the question, its options with the recommended one marked and why, links to its context, and who asks. Open questions are on ⌘J after blocked agents and counted beside the drawing toolbar; press a number and Return to answer. The answer reaches the asking terminal with its next prompt, or a script waiting with `easl ask --wait` (which also takes the `{question, options, recommended}` JSON an agent already has). Questions can expire (`--expires 30m`), be cancelled (`easl ask cancel`), and be archived once closed (Archive, or Return on the selected tile, then Return). VoiceOver reads the question, its options and the answer, and presses its options and buttons. API: the `question` object type (`QuestionProps`), validated on create and update, and `object.find` by `type` and `status`.
- **easld serves Mac clients** (schema change: `client.attach`, `text.measure`, `approximate`): a Mac client attaches and serves what needs the app (view.get, view.render, view.snapshot, agent.prompt, agent.read's live modes, object.reload, exact text measurement); easld forwards those calls and answers `unavailable` with no client attached. A client on a newer easl works with an older easld; an older client is refused and told to update. Notes and text shapes are measured from a checked-in glyph table when no client is attached, marked `approximate: true`. easld now passes 23 of the 24 conformance scenarios.
- **File › Open Remote…** lists your tailnet's online Macs and the hosts you opened before (or any ssh host you type), connects to the chosen one's easl over ssh (by its tailnet DNS name, not the name shown, so renamed and namesake Macs reach the right machine), and lists its boards with their root, open state and agent count. An unreachable Mac shows as offline; one without easl running offers to start the installed app (never a development instance). Back and Cancel end the ssh behind them, Retry asks again where it failed, and quitting ends every ssh relay before easl exits (`nc -N` on Linux hosts whose `nc` has it). Picking a board opens it as a remote board (client mode, above). Only the hosts are remembered.

## 0.1.0

easl is a native Mac app: one infinite board where your agents run in real terminals beside your code, a browser, html pages and diagrams.

- **real terminals.** Claude Code, Codex and any CLI agent run unmodified, rendered by libghostty with your Ghostty config.
- **your code, with your language server.** Hover, definitions, references, a git gutter against your branch, and live call graphs.
- **a browser your agents drive**, with the page's errors on the tile.
- **html pages and diagrams** your agents build beside their terminals.
- **reference anything in the next prompt.** Hyper-click a line of code, a DOM element, a note paragraph or a command's output.
- **agents keep running when you quit.** Terminals live in zmx sessions, so quitting or rebuilding easl leaves them working.
- **works with** Claude Code, Codex, opencode and Gemini CLI (before 0.60) with no setup, and omp with one symlink.

Requires macOS 14 or later on Apple silicon.
