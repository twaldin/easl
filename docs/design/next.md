# Next: a Go server, remote boards, the composer, browser parity

What easl builds after 0.1.0, and the decisions behind it. Each section is a lane; the lanes run in parallel and land as their own PRs. When a lane ships, its behaviour moves into docs/design.md and docs/contracts.md, and its section here shrinks to what is still open.

## Architecture: `easld` and the Mac client

- **One server, `easld`, written in Go**, for macOS and Linux. It owns boards and their persistence, the API and its events, zmx sessions, file reads, git, language servers, call graphs, mention context, placement, layout checks, link resolution and arrow routing. Go gives static, cross-compiled binaries, cheap concurrency for many sessions, language servers and streams, a strong standard library for processes, sockets and JSON, and builds in seconds. The code lives in this repository under `easld/`, so the schema, the client and the server change together.
- **The Mac app stays Swift and AppKit.** WebKit tiles, libghostty's Metal renderer with the user's Ghostty config, and AppKit's text input, accessibility and trackpad handling are what make the board feel native, and a cross-platform client would rebuild all of them. A gpui client was considered and rejected: its webview is an experimental native overlay that renders on top of the UI, so web tiles couldn't zoom or layer with the rest of the board. Its terminal would need a renderer written on libghostty-vt. And Zed's editor crates are GPL, which easl's MIT licence can't take in. The client keeps drawing, hit-testing and provisional geometry while dragging; everything else is the server's.
- **`schema/easl-api.json` is the contract.** Go and Swift types are generated from it, as the TypeScript and Python clients already are.
- **easld runs as a per-user launchd agent.** The app bundles it and is its client even for local boards, so boards and the API keep working with the app closed.
- **Several clients on one board**: the server is authoritative, and writes go through the existing object revisions.
- **`easl render`** is drawn by a connected Mac client, so it matches what the user sees. With no client online it fails `unavailable`; `get` still works.

### The client protocol

How a Mac client attaches to easld and answers calls that need its drawing or app frameworks. A remote-board viewer serves `view.get`, `view.render`, `agent.prompt`, `agent.read`, `object.reload`, `browser.call`, HTML `object.measure`, and `text.measure`. It uses its own tiles, AppKit and WebKit, never another delegated call to easld. Browser commands, reload and explicitly targeted browser renders select the persisted drawing identity and use that Mac's real page, including its background canvas. Board and region renders use the selected viewer's native providers and current browser stream images. Disconnected browser streams report failed tiles rather than successful retained frames. Diagram reload uses the viewer's host-bound language service and returns the graph for easld to validate and persist. Snapshots remain unserved because a viewer-local image file would persist mirrored content on the wrong machine.

- **Attaching.** A client sends `client.attach` with its schema `version` and hash, `app`, `host`, persistent app-home `identity`, served methods, open boards and optional focus. A board may be in a window, tab or background attachment. The reply's `cli_…` identifies the connection, not the drawing machine. Each attach replaces capabilities and boards; closing detaches. `client.list` includes the persistent identity. Board-scoped `client.changed` events carry full transient client snapshots. A bootstrap list cannot replace a newer event.
- **Versions.** Two Macs on different easl versions is the normal case for remote boards. The schema's `version` changes only with a breaking change. A client built from easld's `version` or a newer one works with it whatever their `schema` hashes, each using the methods both know: easld ignores `client.attach` params and `serves` names it doesn't know, never sends a method the client doesn't list, and a client that gets a param it doesn't know fails just that call. A newer client learns easld's `version` from the reply and speaks that one: keeping older servers working is the newer side's job, since easld can't know what came after it. An older client can't know easld's breaking changes, so it is refused `unavailable`: `easl 0.1.0 on studio is older than this board's server (schema version 1, the server's 2); update it`. The schema hash is the first 16 hex digits of the SHA-256 of `schema/easl-api.json`, generated into both sides (`api.SchemaHash`, `ApiParams.schemaHash`); it tells a client which server it talks to, and logs name it.
- **Framing.** The connection stays an ordinary one: the client's own requests and, after events.subscribe, events go on as before. On top of them easld writes requests to it, `{id, method, params}` with ids `easld-<n>`, and the client answers each with a response line carrying that id (`{id, ok: true, result}` or `{id, ok: false, error}`), in any order, several at a time. A line from the client with `ok` and no `method` is an answer. The client must answer `text.measure` without waiting on easld, which may be holding a board while it measures.
- **Forwarding.** easld checks a delegated call before forwarding it with the same method. It resolves `board` for views and HTML measurement, and `target` for terminal calls. Render transport always uses `inline:true` with no `out`; the viewer returns bytes, and easld writes any file the caller requested on the daemon's own host. HTML measurement carries the resolved candidate props and width, including for fitted writes. Diagram reload sends an authoritative private object snapshot; easld validates and persists the returned graph, then exposes only its summary. Other successful answers and client errors pass through. `agent.read` with `final` stays easld's. For `agent.prompt`, easld queues `mentions` and forwards the call without them; a client error withdraws those mentions.
- **Choosing a client.** Ordinary delegated calls select clients that serve the method and show the call's board, or any serving client for `text.measure`. They prefer the client whose user focused this board last, then focused most recently on any board, then attached last. Browser calls, browser reload and explicitly targeted browser renders instead select only `props.drawingMachine.id`. A creating eligible Mac supplies a new tile's default, otherwise the earliest eligible attached Mac; the first eligible attachment fills existing missing values. Focus and reconnect never move an assigned page. The stored `host` label makes an offline owner readable after disconnect or server restart.
- **Deadlines.** Browser `object.reload` waits for `timeoutMs` plus 5 s, and `view.render` for `timeoutMs` plus 30 s. Defaults are 15 s for browser reload and 8 s for rendering. Browser page commands have 30 s plus 5 s grace; `browser.wait` uses its rounded timeout, capped at 600,000 ms, plus grace. Diagram reload defaults to a 60 s caller wait; a timeout returns `loaded: false` without cancelling computation. Its separate client ceiling is 8h49m30s, a conservative allowance built from graph limits, language-request deadlines and safety margins. A valid graph can publish after the caller's wait. HTML `object.measure` has 25 s, allowing host-file reads and an in-flight reply. Other limits are 5 s for `view.get`, 30 s for `view.snapshot`, 10 s for `agent.prompt` and `agent.read`, and 2 s for `text.measure`. A missed client deadline is `unavailable`; a late client answer is dropped. Only text measurement falls back to the glyph table.
- **Disconnects.** A client that goes away with calls in flight fails each one `unavailable` (`easl 0.2.0 on studio (client cli_…) disconnected before answering view.render`). Nothing is retried on another client: a prompt may already be typed.
- **Terminals are interim.** agent.prompt's paste and agent.read's live modes go to a client only until easld runs zmx sessions on the board's host (the terminals port, below); then easld serves them itself, and agents on a headless board (no Mac attached) keep working. The shapes are chosen so callers don't notice the move: the same methods, params, results and errors, and only the no-client `unavailable` goes away.
- **No client.** Each delegated method fails `unavailable` and says what it needed:

  | Method | Message |
  | --- | --- |
  | view.get | `no app shows board brd_…: view.get reads its window (viewport, selection, focus)` |
  | view.render | `no app shows board brd_…: view.render is drawn by the app, as the user sees the board` |
  | view.snapshot | `no app shows board brd_…: view.snapshot is a picture of its window` |
  | agent.prompt | `no app shows board brd_…: agent.prompt types through the terminal's live surface` |
  | agent.read | `no app shows board brd_…: agent.read reads the terminal's screen through its live surface (final: true needs none)` |
  | browser.call, browser object.reload, single-browser view.render | `draws on <host>, which is offline`; without an assignment, `<id> has no drawing Mac yet` |
  | object.measure, HTML size fit | `an html page is measured by the app` |

- **Text measurement.** `text.measure` takes `items`, each a `kind` and its `text`, and answers their `sizes` in order: `note`, markdown laid out at a frame `width` (default 280) with its fences and images read under `root`: the frame and its `tableShortfall` (ObjectMeasure.note); `text`, a text shape at `textSize`, wrapped at `width` or unwrapped (ObjectMeasure.textBounds); `label`, a rect or ellipse's label wrapped at `width`; `arrowLabel`, an arrow caption's chip (DrawingStyle.arrowLabel); `caption`, a code tile's caption strip (ObjectMeasure.captionWidth). easld sends one batch per operation: object.measure and `size: fit` one item, layout.check every note, text shape, caption and arrow label it checks, and arrow routing the captions it has no exact size for yet (exact sizes are kept per caption, so routing asks once). Agents may call it too.
- **The glyph table.** With no client, or one that doesn't answer in time, easld measures from `easld/internal/measure/glyphs/glyphs.json`, extracted on a Mac by `swift scripts/glyph-widths.swift` and checked in; no font files ship. It has a face for each way NoteRenderer, CodeCaption and DrawingStyle set text: SF Pro (the system font) at 13 pt for notes' body (regular, and with emphasis and strong added) and h4 (semibold, likewise), 15 pt semibold for h3 (likewise), 17 and 20 pt bold for h2 and h1 (with emphasis), 10.5 pt medium and bold for fence captions, 11.5 pt for code captions; SF Mono at 11 pt (code in captions), 11.5 pt (fence rows) and 0.9 times 13, 15, 17 and 20 pt (inline code); Shantell Sans at 15 pt (arrow labels), 18 pt (shape labels) and 20 pt (text shapes, scaled for other text sizes). Each face has the advance of every code point in ASCII, Latin-1, Latin Extended-A, general punctuation and the symbols the app draws (arrows, ⌘ ⌥ ⇧ ↩, ☐ ☑ ⚠ ✓), with font fallback as CoreText does it; a default advance for any other character (1 em for East Asian wide characters and emoji); and its line height as TextKit sets a line of it.
- **The approximation.** Text is laid out run by run, each run in one face: a line is as wide as the sum of its advances and as tall as its tallest face times the paragraph's line height multiple; lines break after spaces, and a word wider than the line breaks between characters. Notes follow NoteRenderer block by block: headings, paragraphs, lists and quotes with their indents and spacing, fences as a caption and rows, tables with NoteRenderer's column widths, rules and images. Kerning, ligatures and AppKit's line-breaking rules are left out, so a size can be a few points off and a line near the edge can wrap differently.
- **`approximate: true`.** Sizes based on the glyph table carry this field in direct measurement, fitted writes, batches, text measurement and affected layout findings. Exact client sizes omit it. A client's fallback HTML size retains its approximation marker in direct measurement and fitted-write results.

HTML measurement uses `object.measure` on a client serving the board. The viewer lays the page out through the existing offscreen WebKit path, with host-file reads and the same title-bar, zoom and height-cap arithmetic as a local tile. Exact answers omit `approximate`. A fallback answer marked `approximate:true` retains that field in both measurement and fitted-write results. With no capable client, HTML remains unavailable rather than using an invented size.

Background attach is on by default under easl › Keep Remote Boards Attached. The app retains a closed sole-tab easld controller and serves its canvas without showing a window. `remote-boards.json` records the SSH target, server home and board id, so restoration reaches the same easld after restart. A manually closed tab or `board.close` removes its entry. Turning the setting off releases hidden attachments but keeps the addresses; turning it on restores them offscreen. Quit ends the connections. A drawing Mac's browser commands and reload use this same retained canvas and local profile.

### Getting there without breaking anything

1. An **API conformance suite** (`conformance/`, docs/testing.md): scripted scenarios recorded from a development instance of the app, normalised for ids, times, revisions and paths, that replay against any socket and diff. The methods that need the Mac client (view.*, agent.prompt/read, object.reload) are marked as delegated. What easld adds beyond today's API (the client protocol: several clients on one board, forwarding, versions, deadlines and disconnects, no client) is recorded against easld with scripted clients.
2. **easld runs the API conformance suite** (`easld/`, docs/testing.md). Exact AppKit text measurement through a connected Mac and glyph-table fallback have shipped. The remaining ports are:
   1. `text-host-dependencies`: exact text measurement for notes with host-file fences or images. The viewer refuses these items rather than reading local files; easld uses its glyph-table approximation, marked `approximate: true`.
   2. `changes-measure`: changes-tile measurement on easld (`easld/internal/measure/measure.go`, `ChangeSet`, `ChangesMetrics`).
   3. `headless-terminal-api`: `agent.read` live modes and typed `agent.prompt` without a Mac client. With `--own-terminals`, easld already owns zmx sessions and serves `agent.read final` and integrated agent messages; live screen reads and typed prompts still delegate to a viewer.
3. **The app attaches as easld's client for remote boards.** It serves its retained canvas, attached terminal surfaces and AppKit text measurement. Local boards still use the in-process server. Every tile provider renders from its native model, host data or current browser stream without delegating render back to easld.

Server-side features (the all-agents overview, supervision stats, review passes, remote boards) are built on easld, not on today's app.

## Remote boards

- **One machine does the work per board**: the machine with the repository is the board's host. Either Mac can open the other's boards, and the mechanism is the same in both directions.
- **SSH over Tailscale is the only transport.** There's no network server and no new authentication. easl lists online tailnet peers with `tailscale status --json`.
- **File › Open Remote…** picks a machine and then one of that host's boards (repository, path, agent count), or Browse… for a new directory over ssh. If easl isn't running on the host, the viewer starts the installed app over ssh (`open -g /Applications/easl.app`, which needs a logged-in GUI session there; never a development instance, whose launcher isn't known). An unreachable host shows as offline.
- **The viewer draws the board natively.** It reads the snapshot and events over the host's socket, forwarded by ssh (`EASL_SOCKET` already accepts any socket path). Terminals attach with `ssh <host> zmx attach <session>`, and the host serves files, git and language servers.
- **Browser tiles name their drawing Mac.** Mac-hosted boards default to their host and retain the existing SSH frame/input stream. Easld boards draw on the persisted attached-client identity in `drawingMachine`. Agents reach that page through easld's caller-bound owned-session cmux socket and exact-client delegation. Profiles and cookies stay on the drawing Mac. Easld relays that Mac's frames to other viewers, and the title-bar selector moves execution among attached Macs. Disconnect never migrates a page.
- **Offload**: shipped for terminals (docs/contracts.md "Hosted terminals"): `props.host`, sessions under the host's easld in its capped slice, one ssh connection per host, easld relaying the board's sockets back (`relay.open`), reconnect, the spool replayed, `scripts/offload-setup.sh`. Remaining tasks from the 2026-10-13 intake:
  - `offload-clone`: provision the agent's clone on the terminal host. Today the session uses whatever `cwd` names there.
  - `offload-file-host`: bind file tiles to a hosted terminal's machine, independently of the board host. Native code and changes tiles already read a remote board host's files; this does not supply files from a different `props.host`.
  - `offload-foreground`: read a hosted terminal's foreground program from that host's process table.
  - `offload-reconnect`: investigate the reported first-call 20 s timeout before relay establishment after reconnect. This was observed once against deckbox, not established as a current reproducible defect. Relay restoration after an easld restart shipped in 0.2.6; that is not proof that this separate reconnect report is resolved.
- **Boards wholly on an easld host** (`--own-terminals`, docs/contracts.md "Owned terminals"): easld owns the agents of its own boards, so they never wait on a Mac's load. Shipped: their sessions start with the terminal and end with it, pointed at easld's socket (agent.report, agent.inbox and the spool reach it), in its `<home>/zmx`; after a reboot easld reopens the boards it had open and starts each missing session, resuming `props.agent` (`AgentResume.argv` ported, one fixture for both), an easld restart starts nothing, and easld-labelled sessions without their terminal end after a grace; easld serves `agent.restart` of them with no client (`AgentResume.relaunch` ported, one fixture for both) and `agent.list`'s `live`/`pid` from its sessions. `board.close` removes a board from its reopen list, keeping sessions unless `endSessions` is true. A Mac viewer uses `<easld home>/zmx` on easld hosts, including macOS, and attaches with `ZMX_DIR` set, while installed Mac app hosts keep their GUI `TMPDIR`. Its attach shares the hosted terminal's three-label ownership check and false-shell guard. The home label comes from the discovered socket directory; `board.get` reports optional merged board IDs before the viewer creates tiles. The viewer waits through `agent.restart` gaps and holds an ownership refusal without attaching. Still open are headless `agent.read` and typed `agent.prompt`.
  Before opening a Mac board, the viewer identifies its server through `client.list` on the loaded board's link. An identified easld has no app-bundle launcher, including at the Mac's default home.
- **Agent addresses stay `name@board`, never host** (docs/contracts.md, Agent addresses). Messages between agents whose boards live on different hosts (`name@board@host`: an agent on the work Mac's board writing to one on the home Mac's) are out of scope for now: an address resolves only among the boards of the server it is sent to. An offloaded terminal talks to its board's server over the forwarded socket, so it addresses and is addressed like any terminal on that board.

## Client mode

Shipped on the Swift app (docs/design.md "Client mode (remote boards)", docs/contracts.md "Remote boards"): `AppDelegate.openRemoteBoard(host:board:)` opens a window mirroring another easl's board (`BoardMirror`: subscribe, read, apply the host's events by `rev`). User creates, moves, resizes, edits, deletes, and question answers are previews sent to the host. Terminals attach to host sessions. HTML, image, video, code, changes, and diagram tiles draw on the viewer from host data. Every schema object has a native viewer renderer, listed in the provider table in docs/design.md. Code navigation, hover, Outline, and Go to use host files and language servers. Easld delegates call-graph building and persists validated graphs as bookkeeping. Browser tiles use connection-owned full-frame streams with private credit and input on the drawing Mac's existing page, directly from a Mac host or relayed through easld. Single-browser renders select that drawing identity. Multi-object and rectangle renders use the selected viewer's providers, including current browser streams with failed offline states. Easld viewers can move drawing among attached Macs through the title bar. Main-frame file inputs upload viewer-picked files in memory. HTML state and links write to the host. Image, code, changes, and diagram tiles poll host metadata while live. Both hosts own per-viewer guarded undo/redo and stacking, seed attention snapshots and acknowledge seen markers and turns, and queue full staged composer mentions per terminal for the matching submission. These require schema version 2. Conformance covers `client-mode`, `remote-undo`, `remote-attention`, easld's delegated `remote-composer`, direct `browser-surfaces`, and `client-surface-relay`. Remote content stays off disk. Still open:

- Remote HTML host-private HTTP(S) GET/HEAD shipped in [#141](https://github.com/twaldin/easl/pull/141). Remaining networking work is stateful HTTP methods, cookie sessions, private WebSockets/HMR, and browser APIs not wrapped by the host runtime.
- [#109](https://github.com/twaldin/easl/pull/109) follow-ups:
  - `html-anchor-preconnect`: investigate clicked-anchor preconnect bypassing the page's network policy. This is source-inferred from WebKit, not reproduced on shipped WebKit. The fixed remote rule list already guards link-tag connection hints and anchor ping.
  - `remote-question-links`: route question file and path links through the board host, refuse viewer-local file opens, and redact remote external-link diagnostics (`QuestionTile.open`).
  - `remote-export-diagnostics`: omit remote object identifiers from Copy as Markdown diagnostics (`copyNoteMarkdown` in `Export.swift`).
- Switching drawing machines on Mac-hosted boards. Easld boards already relay browser streams and offer the title-bar selector; the Mac host still needs attached-client admission, exact page-command routing, and a relay before it can hand drawing to a viewer.
- Folder uploads, iframe file inputs, uploads above 8 MiB, rich clipboard, precise IME caret placement, iframe select handling, and OS-native fullscreen, drag and menu surfaces. Main-frame file inputs already transfer viewer-picked files in memory. Copy and paste remain explicit plain text; cut is refused. Downloads remain drawing-Mac-only. Media permissions, client certificates, and external-app links are refused.
- Private clipboard markers for native browser address and dialog field editors, and an input-completion barrier on WebKit versions without pending-key processing SPI. Page-body Copy already uses private markers; the conservative frame watermark remains unconfirmed when the SPI is absent.

## The composer

Shipped on both hosts (docs/design.md, Composer; docs/contracts.md, Remote boards): full staged targets, token ordering, private tray withdrawal without undo, per-terminal folded submission matching, retained peeks, Codex answer grace, and submitted/returned notifications. Drafts and original captured targets remain private to the viewer. Nothing open.

## Links

Shipped (docs/design.md, docs/contracts.md `view.open_url` and the terminal's `open`/`BROWSER` shim): every web link opens a browser tile beside where it came from, a tile already showing the address is reused, and ⌥-click forces the default browser. Nothing open.

## Browser parity

Shipped (docs/design.md, Browser): popups with `window.opener`, downloads, uploads, JavaScript dialogs, HTTP auth and client certificates, camera and microphone prompts, location, print, find, fullscreen, app links, profiles, tile reuse, reload on file change, and a user agent that tracks Safari. Still open:

- Passkeys for arbitrary sites need Apple's managed `com.apple.developer.web-browser.public-key-credential` entitlement, which an organization developer account requests, so they're parked.
- Notifications: WebKit offers no public permission hook, so `Notification` requests stay denied.

## Backlog in scope

- An all-agents overview across machines: ⌘J visits every board open on this Mac (docs/design.md, Interaction); boards hosted on another Mac or an offload host would join the same tour.

- Review passes: show only unstaged changes, and a "since last review" bookmark.

## Performance and monitoring

The remaining gate tasks are `perf-serial-cpu` and `perf-pan-stretch`, tracked by the measured results in [#33](https://github.com/twaldin/easl/pull/33) below. Those historical results do not qualify current main. Later performance work is not evidence that these targets now pass; both need a fresh measured qualification.

The benchmark (`scripts/perf-loop.py`, docs/testing.md), burst-coalesced off-main routing, the API activity hold, direct `board.get` JSON, parked HTML pages and the monitoring (`app.metrics`, `easl metrics`, the HUD, signposts, the 250 ms log line) shipped; docs/design.md "Performance" has them. Against the targets (139-write burst under 3 s of CPU, no main-thread stretch over 100 ms, at most 2 board routings per burst, idle poll hitch under 16 ms, hidden within 2× of visible), on the sanitized replica of the real board with the window shown on a virtual screen, medians of 3 interleaved runs, before (f3cf58f) → after:

- **Serial burst**: CPU 15.1 → 5.3 s, longest main-thread stretch 224 → 84 ms, board routings 78 → 2. The CPU left was mostly `object.measure`, which built a WKWebView per page (76 measures); phase 2 pools them (`HtmlMeasurePool`, up to 3). A pooled measure still takes ~255 ms of wall time, and the `sample` shows measures navigating the pooled view into new WebContent processes (WebKit swaps processes on a cross-site navigation), so the pool saves the view but not, it seems, the process.
- **Batch burst**: CPU 4.3 → 4.3 s (the same measures), longest stretch 293 → 134 ms, in the batch's own turn (its 101 writes, events, refits and the arrows following them) plus measure teardown. Phase 2, profiled headless (`sample` and a per-turn breakdown of the stretch, single runs, not the 3-run A/B): the stretch was 94–95 ms, one wake of the main thread holding the batch's own turn (~20 ms: writes, events, view updates), the first draw after it routing each of the 19 arrows bound to moved tiles alone (~24 ms of a ~40 ms display turn), and the card of the batch's new tile loading a WebContent process (~24 ms). Arrows out of view now follow on a wake of their own, and cards and model installs queue one per wake (`MainTurns`, at the run loop's `beforeWaiting`), so the loop sleeps and commits between them: 54–58 ms.
- **Idle poll** (`board.get` every 10 s): longest stretch 33 → 8.7 ms.
- **Pan and zoom**: #28's numbers (0.1 ms; HTML pages loaded 11 times, reused 0 times) were the scenario's, not the app's. Its replayed trackpad scrolls never moved the view (a precise scroll is NSScrollView's own, the pointer sat on a live page, and nothing moves in a window on an unviewed Space), its three zoom steps (to 67%) never reached the card threshold (30%, 27% for a live tile), so no page ever went to its card or parked, and the scroll burst's own DevPerf span ended the scenario's, which measured 0.1 ms of it. It now pans with ⌘-wheel notches (the window hands them to the canvas whatever is under the pointer), adds a zoom to the whole board and back, and sums every DevPerf span in the scenario. Headless, one run of phase 2: 2 loads, 18 reuses, longest stretch 50 ms; pages park on that path, and neither the 30 s window nor the 12-page cap evicted one.
- **Hidden vs visible**: 1.00× before and after, so the 4–6× slowdown seen on Tim's machine didn't reproduce here; the activity hold is in place regardless. Headless runs can't measure it: the window is occluded either way.
- **Remeasured** (2026-10-07, registered with bench and judged valid: 3 runs interleaved, windows measured on Space 6, base 5da311a and phase 2 a9928c6, each plus the dev-frame change (#57), synthetic board; medians of 3 [range], a claim only with full separation): serial-burst CPU **5.43 → 3.17 s (−42 %, separated)**, longest stretch 57.5 → 36.9 ms (−36 %, separated); batched-burst CPU 4.53 → 2.38 s (−47 %, separated), longest stretch 64 [60.3–285.8] → 46 [45–60.5] ms (−28 %, not separated: the ranges overlap, 60.5 ≥ 60.3; one base run was 285.8 ms); poll-idle not separated (CPU 1.20 → 1.31 s, longest stretch 10.5 → 11.3 ms); pan-zoom equal on page loads and reuses (18 = 18, 42 = 42), its longest stretch 95.1 → 101.2 ms not separated. Two gates still fail on phase 2: serial-burst CPU, which fails on base too (phase 2 3.17 s, base 5.43 s, against the under-3 s target); and pan-zoom's longest stretch, which fails on phase 2 only (101.2 ms against the under-100 ms target; base's 95.1 ms passes), though the move isn't separated, so it isn't a claimed regression. Full result with disclosures: perf/pr33-result.md on branch perf/results. Current runs use a claimed Space through `EASL_DEV_SPACE`, or `--headless` on an unviewed parking Space.
- **Label placement** is still global per board routing (twice per burst, off the main thread); phase 2 keeps a label whose line and caption are unchanged and nothing within 24 pt of it changed (`ConnectorRouter.keptLabels`), and a routing of the replica now takes ~85–110 ms (headless single runs). Incremental placement for only the affected arrows isn't done.
- **A terminal's display links**: the frame-link patch (Vendor/libghostty-spm/CANVAS-PATCH.md) gives each terminal view a paused `NSView.displayLink` instead of recreating MSDisplayLink's `CVDisplayLink`, which took a shell printing every 400 ms from 30 to 20 display-link threads in a 5 s `sample`. The 20 left are libghostty's renderer starting and stopping its own `CVDisplayLink` per output burst (upstream `generic.zig` `syncDisplayLink`; ~37 µs per start and stop on the renderer thread, nothing on the main thread). They stay until upstream gives `syncDisplayLink` an idle grace period; `window-vsync = false` would remove them at the risk upstream warns of (kernel panics on macOS 14.4+).
